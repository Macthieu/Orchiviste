# S7.1 - Perimetre App Store Muni local

## But exact

L'App Store Muni local doit etre une vue simple du catalogue Muni deja connu par
Orchiviste. Il sert a aider un utilisateur local a comprendre quels modules
Muni existent, lesquels sont utilisables, et quelles actions minimales sont
possibles sans passer par une interface expert.

Ce n'est pas un marketplace distant. Le registre Muni reste la source de verite
locale et le contrat canonique `run --request --result` reste inchangé.

## Vocabulaire minimal

- Module Muni : logiciel ou capacite Muni declare dans le catalogue local.
- Catalogue local : liste des modules Muni connus par Orchiviste.
- Etat visible : statut affiche a l'utilisateur pour comprendre si le module
  peut etre utilise.
- Action module : commande simple exposee depuis la fiche ou la carte du
  module.
- Facade employe : parcours simplifie disponible pour certains modules, sans
  passer par `Pilotage > Lancer`.
- Mode expert : orchestration existante conservee dans `Pilotage > Lancer`.

## Etats visibles des modules

- `installe` : le module est declare localement et ses metadonnees sont
  connues.
- `active` : le module peut etre affiche et propose dans le catalogue local.
- `desactive` : le module est connu mais masque ou bloque volontairement pour
  l'usage courant.
- `non disponible` : le module est declare, mais son executable ou une
  dependance locale manque.
- `erreur` : Orchiviste ne peut pas determiner correctement l'etat du module
  ou detecte une configuration incoherente.

Ces etats doivent rester descriptifs. Ils ne doivent pas declencher de logique
metier parallele ni modifier le comportement des moteurs Muni.

## Actions minimales exposees

- `ouvrir` : acceder au parcours principal disponible pour le module.
- `voir details` : consulter les informations utiles du module : nom, mission,
  disponibilite, raison d'indisponibilite et type d'usage.
- `activer` : rendre visible un module connu si cette capacite existe deja dans
  le registre local.
- `desactiver` : masquer ou bloquer un module connu si cette capacite existe
  deja dans le registre local.

Les actions `installer` et `retirer` restent hors perimetre pour S7.1. Elles ne
devront etre reconsiderees que si le registre local possede deja une notion
claire de module present sur disque, sans telechargement distant ni mutation de
moteur metier.

## Hors perimetre a ce stade

- telechargement ou installation depuis Internet ;
- marketplace public ou prive distant ;
- gestion de versions complexe ;
- signature, paiement, licence ou distribution de modules ;
- installation automatique de dependances systeme ;
- retry generique multi-apps ;
- changement des moteurs Muni ;
- changement du contrat canonique ;
- refonte de `Pilotage > Lancer`.

## Limites avant implementation

- ne pas creer de logique metier parallele dans le catalogue ;
- ne pas inventer d'etat sans source de verite dans le registre Muni ;
- ne pas exposer une action si elle n'a pas de comportement local clair ;
- ne pas rendre l'activation equivalente a une installation ;
- ne pas melanger actions employe et orchestration expert ;
- ne pas generaliser a tous les modules Muni tant que seuls certains parcours
  employe sont stabilises.

## Decision proposee

S7.1 fige l'App Store Muni comme un catalogue local minimal : lecture claire des
modules, etats simples, actions bornees et aucune derive vers un marketplace
complexe.

## Pret a ouvrir S7.2

Le plus petit lot `S7.2` propose est :

`S7.2 - Vue catalogue Muni locale en lecture seule`

Objectif : ajouter ou ajuster une vue catalogue Muni qui affiche les modules
connus, leurs etats visibles et leurs actions disponibles, sans modifier les
moteurs Muni, sans ajouter d'installation distante et sans changer le contrat
canonique.
