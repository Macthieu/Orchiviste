## Usage
Use this playbook when a run fails or enters `needs_review` in Pilotage/Historique.  
Goal: decide quickly between:
- immediate correction + retry
- stop and no apply (`No-Go`)

---

## Incident 1 - Bundle invalide / illisible

Symptome:
- `regles_source=fallback_local` unexpectedly
- explicit bundle read/parse error in result
- rule contract absent in loaded context

Diagnostic attendu:
- bundle path unreadable, missing, or malformed JSON
- absence of usable `naming_rule_contracts`

Cause probable:
- wrong path
- stale generated file
- corrupted bundle export

Action immediate:
1. Regenerate bundle from valid inputs (`classification_path`, `rules_path`, `guide_path`).
2. Re-run preview with regenerated `regles_bundle_path`.
3. Confirm target `rule_id` exists in `naming_rule_contracts`.

Decision Go / No-Go:
- `No-Go Apply` until valid bundle is loaded and preview succeeds with expected trace.

---

## Incident 2 - Metadata absente / invalide

Symptome:
- metadata read/parse error
- missing document fields in preview diagnostics
- fallback triggered with explicit fallback reason

Diagnostic attendu:
- `document_metadata_path` missing/unreadable/malformed
- extracted payload incomplete for intended rule

Cause probable:
- analyse stage not run or wrong output path
- outdated metadata file
- truncated or malformed JSON payload

Action immediate:
1. Re-run MuniAnalyse extraction.
2. Validate `document_metadata.json` integrity.
3. Re-run preview on same working scope.

Decision Go / No-Go:
- `No-Go Apply` until metadata is valid and required fields are present.

---

## Incident 3 - Regle introuvable / non applicable

Symptome:
- `regles_rule_id` not resolved
- template application skipped
- fallback reason indicates rule mismatch or unsupported applicability

Diagnostic attendu:
- selected rule missing from bundle
- rule exists but cannot be applied on current metadata scope
- `required_metadata_fields` not satisfied

Cause probable:
- typo in `regles_naming_rule_id`
- wrong bundle version
- metadata insufficient for the selected template

Action immediate:
1. Verify `regles_naming_rule_id` against bundle contracts.
2. Check `required_metadata_fields` for selected rule.
3. Either fix metadata inputs or choose an applicable rule.
4. Re-run preview only.

Decision Go / No-Go:
- `No-Go Apply` while rule resolution/applicability is not explicit and stable.

---

## Incident 4 - `plan_digest` / `expected_plan_digest` incompatibles

Symptome:
- apply rejected due to digest mismatch
- apply result indicates digest gate failure

Diagnostic attendu:
- preview digest and apply expected digest differ
- inputs changed between preview and apply

Cause probable:
- source folder changed after preview
- metadata or bundle changed
- stale operator copy/paste of digest value

Action immediate:
1. Stop apply attempt.
2. Re-run preview on current, unchanged scope.
3. Capture fresh `plan_digest`.
4. Re-launch apply with exact `expected_plan_digest`.

Decision Go / No-Go:
- `No-Go Apply` until digest lock is re-established from a fresh preview.

---

## Incident 5 - Collisions bloquantes / destination existante

Symptome:
- collisions reported in preview/apply diagnostics
- rename plan cannot be executed without conflict
- destination path already occupied

Diagnostic attendu:
- deterministic collision diagnostics present
- idempotence and collision entries clearly separated

Cause probable:
- multiple files map to same target name
- existing destination file conflicts with target
- naming inputs too coarse

Action immediate:
1. Do not apply.
2. Resolve naming ambiguity (metadata or rule choice).
3. Re-run preview and confirm collisions are cleared or explicitly handled.

Decision Go / No-Go:
- `No-Go Apply` while unresolved blocking collisions remain.

## Quick Decision Table

| Symptome | Diagnostic attendu | Action immediate | Decision |
| --- | --- | --- | --- |
| Bundle error / fallback unexpected | Bundle unreadable/invalid, no usable contracts | Regenerate bundle, rerun preview | No-Go |
| Metadata error or missing fields | Metadata unreadable/invalid/incomplete | Re-run analyse, validate metadata, rerun preview | No-Go |
| Rule missing/not applicable | Rule unresolved or required fields missing | Validate rule id + contracts, fix metadata/rule, rerun preview | No-Go |
| Digest mismatch on apply | `plan_digest` and `expected_plan_digest` differ | Stop, rerun preview, refresh expected digest | No-Go |
| Blocking collisions | Conflict diagnostics still present | Resolve conflicts, rerun preview | No-Go |

## Operator decision rule
If one blocking incident is active and unresolved: **No-Go Apply**.  
Apply is authorized only after:
1. incidents resolved,
2. fresh preview validated,
3. digest lock confirmed.
