# S3.4 Operations Notes (Decision Apply)

## Objet
Cette note aligne le signal UI `Decision Apply` entre:
- `Pilotage > Lancer`
- `Pilotage > Historique`

Le signal est une aide operateur UI. Ce n'est pas une nouvelle logique metier.

## Role du signal `Decision Apply`
- `No-Go`: ne pas lancer `apply`.
- `Go`: `apply` possible seulement si les autres preconditions operatoires sont satisfaites.

## Difference d'usage
- `Pilotage > Lancer`:
  - signal de decision avant action,
  - support a la decision immediate (preview/apply).
- `Pilotage > Historique`:
  - signal de lecture a posteriori par execution,
  - support a la revue operateur et a la tracabilite.

## Source des decisions operatoires
La decision operateur reste fondee sur:
- les diagnostics visibles dans Pilotage,
- les garde-fous deja existants (dont `allow_destructive` et confirmations `confirm_*`),
- les references operatoires:
  - [S3.1 Runbook Rename Chain](/Volumes/MAC_HDD/Logiciel%20test/MunicipalApps/Orchiviste/docs/S3.1-RUNBOOK-RENAME-CHAIN.md)
  - [S3.1 Incident Playbook](/Volumes/MAC_HDD/Logiciel%20test/MunicipalApps/Orchiviste/docs/S3.1-INCIDENT-PLAYBOOK.md)
  - [S3.1 Operating Profiles](/Volumes/MAC_HDD/Logiciel%20test/MunicipalApps/Orchiviste/docs/S3.1-OPERATING-PROFILES.md)
  - [S3.2 Diagnostics Reference](/Volumes/MAC_HDD/Logiciel%20test/MunicipalApps/Orchiviste/docs/S3.2-DIAGNOSTICS-REFERENCE.md)

Le signal UI `Decision Apply` complete le guidage operateur sans modifier le backend ni les contrats.
