# S7.5 - Cloture App Store Muni minimal

## Objectif

Cloturer le premier palier App Store Muni minimal avant toute mutation reelle
des modules depuis l'interface.

## Palier effectivement livre

- un store local en lecture seule accessible via `/ui/muni/store` ;
- l'affichage des modules Muni connus par Orchiviste ;
- l'affichage de l'etat visible, de la version et de la description quand elles
  sont disponibles ;
- un point d'entree vers les facades employe quand elles existent ;
- un point d'entree vers les fiches techniques des modules ;
- un statut `Pret employe` pour les modules utilisables par un employe ;
- un statut `Technique seulement` pour les modules encore reserves au parcours
  technique ou expert.

## Ce que l'utilisateur peut deja faire

Depuis l'App Store Muni, un utilisateur peut :

- consulter le catalogue local des modules Muni ;
- reperer les modules prets pour un usage employe ;
- ouvrir directement `MuniRenommage` ou `MuniConversion` dans leur facade
  employe ;
- consulter la fiche technique d'un module ;
- voir que `Activer` et `Desactiver` existent comme intentions d'action, mais
  restent non mutables a ce stade.

## Hors perimetre maintenu

- absence volontaire d'activation ou de desactivation reelle ;
- absence volontaire d'installation ou de desinstallation de modules ;
- absence de marketplace distant ;
- absence de changement des moteurs Muni ;
- absence de changement du contrat canonique `run --request --result` ;
- absence de workflow, smoke ou refactor supplementaire dans ce palier.

## Suite eventuelle

Toute extension au-dela de ce palier devra faire l'objet d'une decision
explicite. En particulier, une phase suivante devra cadrer avant implementation :

- le modele local d'activation et de desactivation ;
- les droits, garde-fous et traces attendus ;
- l'impact sur le registre Muni ;
- les validations locales minimales associees.

## Conclusion

Le premier palier App Store Muni minimal est declare en place.
