# S4.2 Daily Operations Check

Date: 2026-04-19  
Perimetre: Orchiviste (verification operateur quotidienne)

## But
Standardiser une verification ultra-courte de la chaine pour demarrer et cloturer la journee avec un niveau de risque maitrise.

## Avant le premier run du jour
- Verifier que les chemins de travail du jour sont corrects (source, sortie, artefacts).
- Verifier rapidement les derniers diagnostics visibles dans Pilotage/Historique.
- Reconfirmer que la logique `preview` puis `apply controle` sera respectee.
- En cas de doute sur preconditions `apply`, utiliser la checklist S3.5 avant tout lancement.

## Apres le dernier run du jour
- Verifier que les derniers runs ont un resultat coherent avec l'attendu operateur.
- Verifier qu'aucune anomalie bloquante n'est laissee sans action.
- Noter les anomalies observees (symptome court + run concerne + action prise).
- Si incident non resolu: ouvrir une escalation selon le playbook incident.

## Anomalies a noter
- `blocking` persistant.
- `plan_digest` mismatch.
- metadata requise manquante.
- collision/destination existante non resolue.
- fallback inattendu non explique.

## Cas d'escalade
- Incident bloque pour le prochain lot.
- Cause non comprise apres verification standard.
- Incoherence entre signal UI et resultat reel observe.
