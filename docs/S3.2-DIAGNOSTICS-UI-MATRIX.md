# S3.2 Diagnostics UI Matrix (Pilotage / Historique)

Date: 2026-04-16  
Scope: documentation de rendu UI uniquement (aucun changement code)

## Objet
Definir, sans ambiguite, comment chaque diagnostic de la chaine rename doit etre affiche:
- quoi montrer
- ou le montrer
- avec quel niveau visuel
- quelle action operateur proposer

## Documents relies
- [Diagnostics Reference](S3.2-DIAGNOSTICS-REFERENCE.md)
- [Operating Profiles](S3.1-OPERATING-PROFILES.md)
- [Incident Playbook](S3.1-INCIDENT-PLAYBOOK.md)

## Convention de rendu
- Niveaux visuels: `info`, `warning`, `blocking`
- Emplacements UI:
  - `Run Card` = carte de run dans Pilotage
  - `Run Detail` = detail complet d'un run
  - `Historique` = liste historique
- Visibilite:
  - `toujours visible`
  - `visible si present`
  - `detail uniquement`

## Regles transversales de rendu

### 1) Ce qui merite un badge blocking
Afficher un badge `blocking` sur Run Card + Historique pour:
- `RG_BUNDLE_UNREADABLE_OR_INVALID`
- `RG_RULE_NOT_FOUND_OR_NOT_APPLICABLE`
- `RG_REQUIRED_METADATA_FIELDS_MISSING`
- `RN_PLAN_DIGEST_MISMATCH`
- `RN_COLLISION_BLOCKING`
- `RN_DESTRUCTIVE_GUARD_MISSING`

### 2) Ce qui doit apparaitre en resume compact
En Run Card/Historique, afficher en resume:
- libelle operateur court
- niveau visuel
- CTA principal (sauf `Aucune`)

### 3) Ce qui reste en detail uniquement
Conserver en Run Detail:
- payloads complets de warnings structures
- fallback reason detaillee
- details collisions/no-op ligne par ligne

### 4) Ce qui interdit un CTA Apply
Masquer ou desactiver `Apply` si au moins un diagnostic `blocking` est present:
- regle operatoire: `No-Go` automatique
- seul CTA autorise: correction et relance (`Re-run Analyse`, `Rebuild Bundle`, `Re-preview`, `Stop Apply`)

---

## Decision UX minimale
- S'il existe un `blocking`: afficher etat global `No-Go`.
- S'il n'existe que des `warning`: afficher `Review required`.
- Sans `blocking` ni `warning`: etat `Go`.

Ce document sert de base unique pour une future evolution UI legere, sans ambiguite de rendu ni de decision operateur.
