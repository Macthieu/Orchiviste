# S7.4 - Criteres Pret employe

## Objectif

Definir un statut simple pour distinguer les modules Muni utilisables par un
employe depuis l'App Store local de ceux qui restent techniques ou reserves au
pilotage expert.

## Statuts retenus

- `Pret employe` : le module dispose d'un parcours employe stabilise.
- `Technique seulement` : le module est connu du catalogue, mais son usage
  reste technique, expert ou incomplet pour un employe.

## Criteres minimaux Pret employe

Un module peut etre marque `Pret employe` seulement si les criteres suivants
sont remplis :

- une facade employe dediee existe ;
- le parcours principal est utilisable sans editer de JSON canonique ;
- le resultat ou retour utilisateur est lisible par un employe ;
- les garde-fous minimum du module sont presents ;
- l'App Store Muni expose un point d'entree clair vers cette facade ;
- l'execution continue a passer par le contrat canonique `run --request --result`.

## Modules couverts a ce stade

- `MuniRenommage` : `Pret employe`, via `/ui/muni/apps/MuniRenommage/employe`.
- `MuniConversion` : `Pret employe`, via `/ui/muni/apps/MuniConversion/employe`.

Les autres modules restent `Technique seulement` tant qu'une facade employe
dediee n'est pas stabilisee.

## Hors perimetre

- activation ou desactivation reelle depuis l'UI ;
- installation ou retrait de modules ;
- marketplace distant ;
- changement des moteurs Muni ;
- changement du contrat canonique ;
- generalisation automatique du statut a tous les modules.

## Decision proposee

Afficher `Pret employe` dans l'App Store Muni uniquement pour les modules avec
facade employe stabilisee. Les autres modules restent visibles, mais marques
`Technique seulement`.
