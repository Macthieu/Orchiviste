# S3.1 Operating Profiles - Rename Chain

Date: 2026-04-16  
Scope: Orchiviste operational documentation only (no code change)

Reference: `docs/S3.1-RUNBOOK-RENAME-CHAIN.md`

## Purpose
Provide two ready-to-use operating profiles for chain execution:
- MuniAnalyse -> MuniRegles -> MuniRenommage (preview)
- MuniAnalyse -> MuniRegles -> MuniRenommage (apply controlled)

This document is designed for operators who need a direct execution guide without re-reading S2 history.

---

## Profile A - Secure Preview

### Objective
Produce a deterministic rename plan with diagnostics, without changing files on disk.

### Expected parameters (minimum)
- Analyse stage:
  - `source_paths`
  - `document_metadata_output_path`
- Regles stage:
  - `classification_path`
  - `rules_path`
  - `guide_path`
  - `bundle_path`
- Renommage stage (preview):
  - `action=preview`
  - `directory_path`
  - `preset_path`
  - `regles_bundle_path`
  - `regles_naming_rule_id`
  - `regles_apply_rule=true`
  - `document_metadata_path`
  - `dry_run=true`
  - `confirm_apply=false`

### Expected outputs
- `document_metadata.json`
- MuniRegles bundle with `naming_rule_contracts`
- Renommage result containing:
  - `plan_digest`
  - rule trace fields (`regles_source`, `regles_rule_id`, versions)
  - fallback and warning diagnostics when relevant

### Diagnostics to verify
- Analyse:
  - `extraction_provenance`
  - structured warnings
- Regles:
  - target `rule_id` exists
  - `required_metadata_fields` present and coherent
- Renommage preview:
  - status is usable (`succeeded` or controlled `needs_review`)
  - `plan_digest` present
  - collisions/idempotence diagnostics visible
  - fallback reasons explicit if fallback occurs

### Stop conditions (do not continue to apply)
- Bundle unreadable/invalid
- Metadata missing/invalid
- Rule missing or not applicable
- Missing required metadata fields
- Critical warnings not understood
- Collision diagnostics unresolved

## Profile B - Controlled Apply

### Objective
Execute file rename only after explicit safety checks and exact digest lock to preview output.

### Mandatory preconditions
1. Profile A completed on same working copy.
2. Valid preview `plan_digest` captured.
3. No blocking collisions unresolved.
4. Rule contract passed (`required_metadata_fields` satisfied).
5. Operator confirms work is on copy, not originals.

### Expected parameters (minimum)
- `action=apply`
- `directory_path`
- `preset_path`
- `regles_bundle_path`
- `regles_naming_rule_id`
- `regles_apply_rule=true`
- `document_metadata_path`
- `dry_run=false`
- `confirm_apply=true`
- `allow_destructive=true`
- `expected_plan_digest=<preview plan_digest>`

### Dependency on digest lock
- `expected_plan_digest` is mandatory.
- Apply is authorized only when:
  - `expected_plan_digest` equals preview `plan_digest`
  - apply result returns matching `plan_digest`

### Minimum validations before execution
- Inputs unchanged since preview (same folder, same bundle, same metadata scope).
- Preview diagnostics reviewed.
- Fallbacks understood and accepted (or corrected before apply).
- No ambiguous operator decision pending.

### Expected apply results
- Controlled rename on target copy.
- No implicit overwrite.
- Deterministic handling of:
  - collisions
  - idempotent no-op cases
- Clear result status + diagnostics.

### Immediate stop conditions
- Missing `allow_destructive=true` or `confirm_apply=true`
- Missing/mismatched digest
- New warnings/collisions introduced since preview
- Unexpected fallback reason
- Target path ambiguity or non-reviewed scope change

## Go / No-Go Apply Checklist

Mark each item before apply:
- [ ] Preview executed successfully on current working copy
- [ ] `plan_digest` captured and archived
- [ ] `required_metadata_fields` satisfied for targeted documents
- [ ] Rule and template validated in bundle (`naming_rule_contracts`)
- [ ] No unresolved collision diagnostics
- [ ] Fallback reasons reviewed and accepted (or corrected)
- [ ] Apply parameters set with:
  - [ ] `dry_run=false`
  - [ ] `confirm_apply=true`
  - [ ] `allow_destructive=true`
  - [ ] `expected_plan_digest=<preview digest>`
- [ ] Operation scope confirmed on non-original files

If any box is unchecked: **No-Go Apply**.

## Operating note
Profile A is default.  
Profile B is allowed only after Go/No-Go checklist is fully validated.
