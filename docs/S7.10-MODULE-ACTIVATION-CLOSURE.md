# S7.10 - Cloture activation locale minimale

## Objectif

Cloturer le sous-bloc d'activation locale minimale des modules Muni, apres
implementation de la mutation locale et ajout de sa preuve de non-regression.

## Livrables du sous-bloc

- `S7.7` : activation et desactivation locales minimales des modules Muni deja
  connus du registre.
- `S7.8` : smoke cible `smoke_muni_store_activation.sh` couvrant le cycle
  `active -> desactive -> active`.
- `S7.9` : integration du smoke dans `scripts/preflight_local.sh --full`,
  avec exclusion explicite du mode `--quick`.

## Ce que l'utilisateur peut maintenant faire

Depuis l'App Store Muni, l'utilisateur peut :

- voir l'etat local d'un module connu : `active` ou `desactive` ;
- desactiver un module connu ;
- reactiver un module connu ;
- conserver l'acces a la fiche technique ;
- continuer a ouvrir les facades employe disponibles quand le module est actif.

La mutation reste locale au registre Muni. Elle ne lance pas de moteur Muni et
ne change pas le contrat canonique `run --request --result`.

## Couverture de non-regression

Le smoke `smoke_muni_store_activation.sh` verifie :

- ouverture du store en `200` ;
- module connu affiche `active` au depart ;
- POST de desactivation ;
- retour store avec etat `desactive` ;
- POST de reactivation ;
- retour store avec etat `active` ;
- absence d'actions installation ou retrait.

Le smoke est execute dans `preflight_local.sh --full`. Il est ignore en
`--quick` pour ne pas ralentir le parcours rapide.

## Hors perimetre maintenu

- installation ou desinstallation de modules ;
- telechargement distant ou marketplace ;
- gestion de versions, signatures, licences ou dependances ;
- mutation des moteurs Muni ;
- changement du contrat canonique ;
- activation automatique ;
- droits complexes ou workflow d'administration avance ;
- refonte du registre, du cockpit ou des facades employe.

## Conclusion

Le sous-bloc activation locale minimale des modules Muni est declare en place.
